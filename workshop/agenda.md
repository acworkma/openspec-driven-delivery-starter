# Full-day agenda

**Audience:** product owners, architects and developers in mixed-role pairs
or small teams. **Length:** eight hours, including breaks and lunch.
The allocations below are teaching blocks, not estimates of engineering effort.

| Block | Minutes | Learning objective and output |
| --- | ---: | --- |
| Welcome, SDD principles, roles, guardrails | 20 | Distinguish intent, requirements, examples and evidence; agree a shared outcome |
| Demonstrate the complete OpenSpec delivery loop | 35 | Trace a requirement through a proposed change, code, tests, PR review and archive |
| 004 Vision-rider retro drill | 40 | Expose missing rules and record a gap log before seeing the answer |
| Break | 15 | |
| 001 Intent, clarification and OpenSpec change lab | 55 | Produce a scoped proposal, clarified privacy rules and reviewable requirement delta |
| Lunch | 60 | |
| 001 Design, Gherkin and task slicing | 45 | Approve observable examples and a bounded build plan |
| 001 JavaScript implementation with Copilot | 90 | Implement the visibility policy and produce passing unit/acceptance evidence |
| Break | 15 | |
| Platform-specific CI and peer PR review | 45 | Run GitHub Actions or Azure Pipelines and review a linked PR |
| Archive/living-spec exercise and readouts | 35 | Inspect how the approved change updates the current contract and preserves history |
| Compare 002/003, adoption decisions and close | 25 | Run the other references and choose a follow-on application |
| Total | 480 | One full delivery loop, with all four business cases represented |

Use the [facilitator guide](facilitator-guide.md) to run each block.
The hands-on outcome is one **bounded slice of 001**, not four production
applications built in one day. Reference code and exercises for all four are
available in the [case catalog](cases/README.md).
